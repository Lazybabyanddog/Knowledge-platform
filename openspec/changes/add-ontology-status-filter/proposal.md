# Proposal

## Why

本体管理页的实体类/关系类型列表把状态藏在名称单元格的一枚小标签里，且只有「失效」有标记，有效行没有任何视觉提示；定义一多，想确认「哪些已经失效」只能逐行扫。列表也没有按状态过滤的能力，停用的定义和有效定义混在同一屏。

前端已经在 `include_disabled=true` 下拿到全量数据（本体条目数量级很小、列表无分页），因此补上状态列与客户端筛选即可解决问题，不需要动后端接口。

## What Changes

- 实体类列表、关系类型列表各新增一列「状态」：`有效` 用成功色标签、`失效` 用灰色标签；删除名称单元格里重复的「失效」小标签。
- tab 右侧新增状态筛选下拉：`全部`（默认）/ `有效` / `失效`，两个 tab 共用一个筛选状态，切换 tab 时保持。
- tab 标题计数改为「当前可见数/总数」，例如 `实体类 3/12`；默认「全部」时显示 `12/12`。
- 筛选只作用于表格数据源，`classMap` / `classOptions`（父类名解析、关系起点/终点下拉）仍基于全量数据，避免失效类从下拉里消失。
- 筛选结果为空时给出区别于「还没有定义」的空态文案。
- 不改后端接口、数据库、`include_disabled` 语义与前端 API 客户端。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `knowledge-graph`: 为「本体管理」新增一条列表展示与筛选需求——列表逐行展示状态，并支持按有效/失效筛选，筛选不改变数据可见范围（全量仍在内存中）。

（说明：`openspec/specs/` 目前为空，`knowledge-graph` 的基线 delta 仍在在途变更 `knowledge-base-platform`；本次只新增该能力下的一条需求，不改动既有需求文本，归档顺序上需先落地或同步基线。）

## Impact

- 前端：`src/views/OntologyView.vue`（筛选状态、两个 computed 视图、tabs 外层布局、两处 tab label、两处表格数据源、两处状态列、两处空态文案、少量 scoped 样式）
- 后端 / 接口 / 数据库 / 图库：无改动
- 风险：Element Plus `2.8.4` 的 `el-tabs` 没有右侧插槽，筛选框位置依赖外层 flex 布局；样式回归只影响本体管理页
