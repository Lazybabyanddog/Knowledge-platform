# 改写实验室：三组对照记录

- 日期：2026-11-22
- 环境：开发环境，真实 LLM + embedding（DashScope），`quality_threshold=0.6`、`top_k=5`、`min_evidence=2`、截止时间 20s
- 语料：`backend/scripts/query_rewrite_benchmark.py` 临时插入 6 篇已发布文档（每篇 1 个片段，真实向量），运行结束即删除；库里另有 1 篇已发布但无片段的文档
- 原始 Trace：`benchmark.json`（15 次运行的完整 `RewriteTrace`，可逐条复算）

语料是合成的小样本（6 篇制度类文本），结论只用于判断方向与成本，不足以当作线上效果。

| ID | 问题 | 考察点 |

## 配置

- **关闭改写**：Allowlist 空，预算 1（仍有 1 次查询理解调用）
- **只开语义改写**：Allowlist `semantic`，预算 2
- **全开**：五个策略，预算 5

## 结论

1. **上下文改写是唯一的大幅提升来源**：q1 的 `+0.4030` 来自把"它"补全为年假问题；没有历史时该策略不触发，不产生成本。
2. **语义改写只在复合/口语问题上小幅有效**：q3 `+0.0198`，其余均在噪声内。只开语义的成本几乎不变（+0.2 次模型调用）。
3. **全开的增益主要来自二阶段 multi**：q2/q5 主链路策略都未触发，是"首轮不充分 → 补充一次 multi"把 `top1` 抬起来的；扩展查询同时把覆盖文档从 5 拉到 6，代价是检索与嵌入查询增多。
4. **20s 截止时间对"全开 + 复合问题"是不够的**：q3 用了 4 次串行模型调用（约 5s/次），改写组检索被取消，页面显示"未完成"并回退对照组。建议实验时把预算降到 3，或调大 `QUERY_REWRITE_TIMEOUT_SECONDS`（如 30）后再比较全开。
5. **阈值判定被合成语料放大**：每篇文档只有 1 个片段，`min_evidence=2` 只能靠跨文档命中满足，因此大量 `insufficient` 是语料结构导致，不代表改写无效；看 `lift` 与达标片段数更可靠。
6. **噪声底约 0.001**：关闭改写组的 `lift` 在 ±0.0006 内浮动（同查询两次 embedding 的差异），`|lift| < 0.005` 一律视为打平。

## 复现

```powershell
cd backend
python -m scripts.query_rewrite_benchmark --out ../openspec/changes/add-rag-query-rewrite/benchmark.json
```

脚本会临时建语料、依次跑 15 组、输出表格与原始 Trace，并在结束时清理语料；`--keep-corpus` 可保留语料用于页面手工核对。运行会调用真实模型并产生费用。
