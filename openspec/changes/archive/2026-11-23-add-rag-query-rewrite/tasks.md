## 3. 策略执行器

- [x] 3.1 实现上下文改写执行器（消费 `history` 补全指代，无历史直接跳过）；验证单测：有历史时输出替换了指代对象的查询，无历史时不产生模型调用
- [x] 3.2 实现语义改写执行器（口语转检索表达），输出与原查询等价时记为跳过且不增加检索次数；验证单测断言等价输出返回 `skipped` 且 `embed_calls` 不增加
- [x] 3.3 实现实体标准化执行器：先查图谱候选，0 候选跳过、1 候选直接采用、多候选才调一次模型消歧；验证单测用 mock 仓库覆盖三种分支，断言模型调用次数分别为 0/0/1
- [x] 3.4 实现问题拆解执行器：产出 ≥2 个可独立检索的子问题并保留"子问题 → 命中片段"映射；验证单测断言子问题数与映射完整性
- [x] 3.5 实现 Multi-Query 执行器：产出 ≥2 条表达角度不同的查询，不改写主查询；验证单测断言主查询未被修改、扩展查询数量正确
- [x] 3.6 实现 `hyde`、`stepback` 的未启用执行器：统一返回未启用原因，零模型调用、零检索；验证单测断言调用计数为 0 且原因字段非空
- [x] 3.7 落实单策略失败隔离：任一执行器抛错时只标记自身降级、其余改写结果照常进入检索；验证单测注入一个失败执行器，断言运行成功且该策略状态为降级

## 4. 双路检索、质量评估与融合

- [x] 4.1 实现双路检索：对照组用原始查询、改写组用主查询 + 扩展查询，两臂共用 `_base_stmt`；验证单测断言两臂产生的过滤条件完全一致、仅有查询文本不同
- [x] 4.2 实现指标计算（`top1`、`above_tau`、`distinct_docs`、相对 baseline 的 `lift`）；验证单测用手工构造的两组命中断言四个数值可复算
- [x] 4.3 实现评估结论判定（`above_tau >= min_evidence` 且 `top1 >= threshold` 为 sufficient）；验证单测覆盖边界值（等于阈值、证据数差 1）
- [x] 4.4 实现二阶段补充：仅在首轮不足、Allowlist 允许且预算未耗尽时发起一次，补充后不再扩展；验证单测覆盖三例——正常补充、Allowlist 未开放则以低置信度结束且零额外调用、补充后仍不足不发起第三轮
- [x] 4.5 实现融合：按 `chunk_id` 去重并记录命中来源，RRF（`k` 取配置）排序，对外 `score` 取各臂最大相似度，输出 `top_k` 并从 1 连续编号；验证单测断言同片段多路命中只出现一次、来源列表完整、编号连续
