# Spec Delta

## Purpose

把解析产物变成可被语义检索的片段，并基于已发布文档提供带引用的流式问答，使沉淀在文档库里的内容可以被直接提问并追溯到原文位置。

## ADDED Requirements

### Requirement: 解析产物切分为可检索片段

系统 SHALL 从解析任务的块产物构建持久化片段（chunk），片段是检索与引用的最小单位。

- 片段内容由连续的、未被丢弃的块合并而成，目标长度由策略配置 `chunk_hint` 决定，默认 800 字；单块超长时按段落边界再切分，保证不出现半句截断。
- 标题块不单独成为片段，而是作为其后片段的前缀上下文；表格块整体保留为一个片段，不与正文合并。
- 每个片段 MUST 记录其来源版本的 `document_version_id`、`parse_task_id`、覆盖的块 ID 列表、起止 `seq`、页号范围与标题路径。
- 同一 `parse_task_id` 重复执行切分 MUST NOT 产生重复片段。

#### Scenario: 正文与标题合并成片段

- **WHEN** 一个解析结果包含标题块 `## 第三章 预算` 与其后 12 个正文段落，合计 760 字
- **THEN** 系统产出一个片段，内容以该标题开头，`block_ids` 覆盖这 13 个块，`page_no` 范围为这些块的最小到最大页号

#### Scenario: 表格独立成片段

- **WHEN** 解析结果中表格块前后各有若干段落
- **THEN** 表格块单独形成一个片段，不与其前后段落合并

#### Scenario: 丢弃块不进入片段

- **WHEN** 某个块 `is_discarded=true`
- **THEN** 该块不出现在任何片段的内容与 `block_ids` 中

### Requirement: 片段向量化与索引构建

系统 SHALL 通过 OpenAI 兼容的 `/embeddings` 接口为片段生成向量，并写入带向量索引的列。

- 请求 MUST 显式传入 `dimensions=1024`，与数据库列定义的维度一致；接口返回的向量长度不等于 1024 时，本次构建判定失败并记录错误，不得写入。
- 向量写入 MUST 与片段内容写入在同一事务内完成，避免出现有内容无向量的片段。
- 索引构建以文档版本为单位，失败时保留失败原因并可由管理员重试，不得产生半成品索引对外可见。
- 未配置 embedding（`EMBEDDING_API_KEY` 或 `EMBEDDING_BASE_URL` 为空）时，索引任务 SHALL 标记为 `skipped` 并给出原因，MUST NOT 阻塞文档发布。

#### Scenario: 维度不一致时拒绝写入

- **WHEN** embedding 接口返回 1536 维向量而系统配置为 1024 维
- **THEN** 该版本的索引构建失败，片段保持无向量状态，任务记录错误码与实测维度

#### Scenario: 未配置 embedding

- **WHEN** 管理员在未配置 embedding 的环境下批准文档发布
- **THEN** 文档状态正常变为 `published`，索引任务标记为 `skipped`，文档详情中索引状态显示"未配置向量模型"

### Requirement: 索引生命周期跟随发布状态

系统 SHALL 只在文档被发布时建立索引，并在文档离开已发布状态时清除索引。

- 审批通过的版本 MUST 成为唯一被索引的版本；同一文档的旧版本索引 MUST 被删除。
- 文档进入 `archived`、被软删除或重新解析产生新解析任务时，其既有片段与向量 MUST 失效或被删除。
- 检索结果 MUST 只包含 `document.status=published` 且 `document_version.is_current=true` 的片段。

#### Scenario: 发布后建立索引

- **WHEN** 审批人对 `status=pending` 的文档执行通过
- **THEN** 文档变为 `published`，其当前版本在后台完成切分与向量化，随后可被检索到

#### Scenario: 下架后不可检索

- **WHEN** 一篇已建立索引的文档被下架为 `archived`
- **THEN** 该文档的所有片段不再出现在任何检索与问答结果中

#### Scenario: 新版本替换旧索引

- **WHEN** 文档的新版本被批准发布
- **THEN** 旧版本片段被清除，只有新版本的片段可被检索

### Requirement: 片段检索与权限过滤

系统 SHALL 提供片段检索接口，按向量相似度返回候选片段，并同时施加可见性过滤。

- 过滤条件 MUST 包含：调用者的 `workspace_id`、`document.status=published`、`document.deleted_at IS NULL`、以及 `sensitivity` 不高于调用者可见级别。
- 接口 MUST 支持指定返回条数上限与可选的文档类型过滤。
- 每条结果 MUST 包含：文档 ID 与标题、版本号、片段内容、得分、页号范围、片段 ID。
- 未配置 embedding 时接口 SHALL 返回 `503` 与明确的错误码，不得返回空列表伪装成"无结果"。

#### Scenario: 只召回已发布内容

- **WHEN** 调用者提问的关键词只出现在某篇 `draft` 文档中
- **THEN** 检索结果不包含该文档的任何片段

#### Scenario: 跨空间隔离

- **WHEN** 调用者属于空间 A，而命中的片段来自空间 B 的文档
- **THEN** 该片段不会出现在结果中

### Requirement: 流式问答与引用

系统 SHALL 提供基于检索结果的问答接口，以 SSE 流式返回答案增量，并在答案中附带可追溯的引用。

- 事件顺序 MUST 为：先推送 `sources`（本次采用的片段列表），再多次推送 `delta`（文本增量），最后推送 `done`（耗时与用量）。
- 生成 MUST 只依据 `sources` 中的片段；片段不足以回答时，答案 MUST 明确说明知识库中没有相关内容，不得编造。
- 答案中引用的编号 MUST 与 `sources` 中的片段一一对应。
- 调用方断开连接时，服务端 MUST 终止上游模型请求并释放连接。
- 未配置 LLM 时接口 SHALL 返回 `503`；生成中途失败时 SHALL 推送 `error` 事件并结束流。

#### Scenario: 正常问答

- **WHEN** 调用者提问且检索命中 3 个片段
- **THEN** 客户端先收到包含 3 条引用的 `sources` 事件，随后收到多段 `delta` 文本，最后收到 `done`

#### Scenario: 知识库无相关内容

- **WHEN** 检索未命中任何片段
- **THEN** 接口不调用模型，直接推送 `sources` 为空与一段明确的无结果说明，并以 `done` 结束

### Requirement: 索引运维与可观测

系统 SHALL 提供索引的可重建能力与状态可查性，便于语料变更后修复。

- 管理员 MUST 能按文档或按全部已发布文档触发索引重建，重建过程不改变文档状态。
- 文档详情 MUST 能展示当前版本的索引状态（未构建 / 构建中 / 已就绪 / 失败 / 跳过）与片段数量。
- 每次问答 MUST 记录审计事件，包含调用者、问题摘要、命中片段数；不得记录完整答案正文。

#### Scenario: 全量重建

- **WHEN** 管理员执行全量重建
- **THEN** 系统为所有 `published` 文档的当前版本重新切分并向量化，完成后片段总数与文档数一致可查

#### Scenario: 问答审计

- **WHEN** 调用者完成一次问答
- **THEN** 审计日志中出现一条问答事件，包含问题摘要与命中片段数
